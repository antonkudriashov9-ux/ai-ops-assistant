# AI Ops Assistant

Telegram-ассистент для первичного разбора инфраструктурных инцидентов. Принимает текст лога, выделяет затронутый компонент, оценивает критичность и предлагает проверки инженеру. Команды на серверах **не выполняет**.

Python 3.11–3.12 · aiogram 3 · OpenAI SDK · Pydantic 2 · SQLAlchemy asyncio · PostgreSQL 16 / SQLite

## Как работает

```text
Личный чат Telegram → проверка Telegram ID → ограничения нагрузки
    → фильтрация распространённых секретов → запись начала в аудит
    → LLM или явно включённая эвристика → строгая проверка структуры
    → запись результата в аудит → ответ инженеру
```

Структура ответа: заголовок, критичность, сервис, объяснение и шаги диагностики. Текст безопасно форматируется для Telegram; длинные ответы разбиваются на сообщения без повреждения HTML и Unicode.

Pydantic проверяет типы, допустимые значения, непустые поля и размеры. **Валидация не доказывает правильность диагноза и не устраняет галлюцинации.** Гипотезы и предлагаемые команды нужно проверять перед применением.

## Быстрый запуск в Docker

Нужны Git, Docker Engine и Docker Compose v2.

```bash
git clone https://github.com/antonkudriashov9-ux/ai-ops-assistant.git
cd ai-ops-assistant
cp .env.example .env
```

Заполните `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `ALLOWED_TELEGRAM_IDS` — непустой JSON-массив ID инженеров, например `[123456789]`;
- `OPENAI_API_KEY` — ключ провайдера;
- `POSTGRES_PASSWORD` — собственный пароль БД, без значения по умолчанию.

Для пароля удобно использовать случайную шестнадцатеричную строку: `python -c "import secrets; print(secrets.token_hex(24))"`. В URL подключения символы `@`, `:`, `/`, `#`, `%` требуют percent-encoding; для автоматически составляемого Compose URL используйте пароль без этих символов.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Compose использует PostgreSQL и сохраняет данные в именованном томе. Файл `.env`, Git-история, базы, тесты и резервные копии исключены из Docker-контекста; образ работает от непривилегированного пользователя. PostgreSQL не публикуется в сеть хоста.

Остановка без удаления данных:

```bash
docker compose down
```

Не добавляйте `--volumes`, если данные нужно сохранить.

Для уже существующего тома сохраните прежние `POSTGRES_USER`, `POSTGRES_DB` и пароль. Изменение этих переменных в `.env` не меняет пользователей и пароли внутри инициализированной БД: обновлять их нужно отдельно средствами PostgreSQL.

## Локальный запуск

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install --require-hashes -r requirements.txt
python -m app.main
```

По умолчанию локальный `DATABASE_URL` указывает на SQLite в `data/aiops_audit.db`. Для PostgreSQL задайте `postgresql+asyncpg://USER:PASSWORD@HOST:5432/DB`. Подмена PostgreSQL локальным файлом автоматически выключена: при недоступности обязательной БД запуск завершится ошибкой. Для сознательного локального резервного режима существует `ENABLE_SQLITE_FALLBACK=true`; это отдельное хранилище, данные обратно в PostgreSQL не переносятся.

Для работы без LLM укажите `ENABLE_MOCK_FALLBACK=true`, оставив API-ключ пустым. Telegram-токен и список доступа по-прежнему нужны. `/demo` всегда использует локальный учебный OOM-пример и не обращается к LLM. Тесты работают без Telegram-токена, API-ключа и сети.

## Команды

| Команда | Результат |
|---|---|
| `/start`, `/help` | Инструкция и примеры входных данных |
| `/demo` | Учебный разбор OOM; явно помечен как демонстрация |
| `/health` | Реальная проверка соединения с БД и состояния записи аудита; конфигурация режима LLM |
| `/stats` | Только ваши счётчики действий, включая команды и начало/результат анализа |

Бот работает в личных чатах. Пустой список ID закрывает доступ. Неизвестные команды, вложения и сообщения без текста получают понятную подсказку.

`/health` не делает платный запрос к LLM и не проверяет ваши серверы. Наличие ключа означает, что провайдер настроен; его фактическая доступность выясняется при анализе.

## Настройки и ограничения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_MODEL` | `gpt-4o-mini` | Модель, поддерживающая Structured Outputs с JSON Schema |
| `OPENAI_BASE_URL` | стандартный адрес SDK | Адрес совместимого API без учётных данных в URL |
| `LLM_TIMEOUT_SECONDS` | `30` | Общий срок запроса, включая повтор SDK |
| `ENABLE_MOCK_FALLBACK` | `false` | Явное разрешение локальных правил при отсутствии ключа или ошибке API |
| `MAX_INPUT_CHARS` | `12000` | Верхняя граница входного текста; дополнительно действует лимит Telegram |
| `MAX_CONCURRENT_ANALYSES` | `4` | Максимум одновременно выполняемых анализов в одном процессе |
| `USER_COOLDOWN_SECONDS` | `3` | Интервал между запросами одного инженера |
| `DATABASE_TIMEOUT_SECONDS` | `5` | Таймаут операций БД |
| `ENABLE_SQLITE_FALLBACK` | `false` | Разрешение отдельного SQLite-хранилища при сбое основной БД на старте |

Один инженер может выполнять один анализ одновременно. При перегрузке запрос отклоняется сразу, без неограниченной очереди. Для одного токена Telegram запускайте один polling-процесс.

При недоступности аудита LLM не вызывается и рекомендации не выдаются. Ошибка схемы, отказ модели и обрезанный ответ всегда блокируются, даже при включённой эвристике. Ошибка провайдера и ошибка формата сообщаются отдельно. Эвристика и демонстрация явно помечаются в ответе и аудите.

Удаляйте пароли, токены и персональные данные **до отправки**. Встроенный фильтр маскирует распространённые ключи, заголовки авторизации, пароли в URI и PEM-ключи, но не распознаёт все возможные секреты. Очищенные логи сохраняются в БД и при LLM-анализе отправляются настроенному провайдеру. Ограничьте доступ к БД и резервным копиям; установите нужную вашей организации политику хранения. Секреты и внутренние ошибки не выводятся в ответы и журналы приложения.

## Резервное копирование

Скрипт `scripts/backup.sh` предназначен для Linux / macOS или WSL с Bash, Docker CLI и gzip. Запускайте его из репозитория, при необходимости задавая `BACKUP_DIR`. Он использует параметры PostgreSQL внутри Compose-контейнера, создаёт сжатый SQL-дамп атомарно и удаляет только свои старые резервные копии. Планирование выполняется средствами вашей инфраструктуры.

```bash
BACKUP_DIR=./backups bash scripts/backup.sh
```

Перед восстановлением остановите бота и проверьте дамп на отдельной БД. Пример восстановления в запущенный PostgreSQL, из корня проекта:

```bash
gzip -dc backups/FILE.sql.gz | docker compose exec -T postgres sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## Проверки и разработка

```bash
python -m pip install --require-hashes -r requirements-dev.txt
python -m pytest -v --cov=app --cov-report=term-missing
python -m ruff check app tests
python -m ruff format --check app tests
python -m pip_audit -r requirements.txt --disable-pip --no-deps
```

Тесты покрывают схему, ошибки и таймауты провайдера, эвристику, авторизацию, форматирование и длину ответов, конкурентные запросы, реальные транзакции SQLite и отказы аудита. Для интеграционной проверки PostgreSQL задайте `DATABASE_TEST_URL` на отдельную тестовую БД: тесты создают и очищают свои данные. Не используйте боевую БД.

Прямые зависимости находятся в `requirements.in` и `requirements-dev.in`. Полные версии с хешами обновляются инструментом `uv`:

```bash
uv pip compile requirements.in --python-version 3.11 --generate-hashes -o requirements.txt
uv pip compile requirements-dev.in --python-version 3.11 --generate-hashes -o requirements-dev.txt
```

После обновления запустите тесты, линтер, аудит зависимостей и Docker build. При изменении схемы БД нужна отдельная миграция; текущие исправления сохраняют существующие таблицу и столбцы.
